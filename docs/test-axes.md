# Test-suite axes

The test suite pins the parser along several independent axes. Each
axis protects a different failure mode. The table below lists the
axes, their corpora, their tests, and their status.

| axis | question it answers | corpus | test | status |
|---|---|---|---|---|
| syntax ground truth | does the grammar parse the spec-correct forms | `tests/fixtures/` | `ground_truth_verify` | done |
| real-file pin | does the parse output stay stable on real files | `tests/real_data/iucr/`, `tests/real_data/cod/`, `tests/real_data/cif_api/` | `real_data_verify` | done |
| space groups | can every one of the 230 groups parse, and is the group tag consistent | `tests/real_data/cod_sg/` | `space_group_coverage` | done |
| lexical/structural features | does at least one corpus file pin each value form | iucr + cod + cod_sg + cif_api + fixtures | `feature_coverage_guard` | done |
| dictionary items | does the corpus exercise the recorded dictionary items | iucr + cod + cod_sg | `dictionary_item_coverage_gate` | done |
| errors | are malformed inputs rejected with a useful report | `tests/fixtures/neg_*` | `ground_truth_verify` | done |
| stress / size | does parsing hold on large files | cod `1542340` (120 KB), iucr `example_shelxl2013` | feature guard row `large file` | partial |
| encoding | CRLF, BOM, UTF-8 handling | fixture 10 (CRLF), fixture 20 (UTF-8), cif_api `bom.cif` (BOM), cif_api `unicode.cif` (UTF-8) | feature guard rows, real-data pins | partial |

## Corpus layout

- `tests/fixtures/` – hand-written syntax fixtures plus `neg_*`
  error cases. Expected JSON is generated by
  `cargo run --example gt_generate`.
- `tests/real_data/iucr/` – the IUCr published example files.
  Full canonical-IR pin in `tests/real_data/expected/`.
- `tests/real_data/cod/` – six COD entries with interesting value
  forms. Full canonical-IR pin in `tests/real_data/expected/`.
- `tests/real_data/cod_sg/` – one COD entry per three-dimensional
  space group (230 files, ~1 MB), with `manifest.json`. Pinned by
  the lighter `space_group_coverage` test, not by a canonical IR.
- `tests/real_data/cif_api/` – the 21 test-data CIFs of the
  COMCIFS `cif_api` reference implementation (the upstream
  project's own edge-case inputs: BOMs, empty files, 2.0 lists
  and tables, triple-quoted strings, nested save frames,
  Unicode, translated EOLs). The CIFs are fetched at test time,
  not committed: `python3 tests/real_data/cif_api/fetch.py`
  (run by the CI workflow) downloads them from the pinned
  commit and verifies them against
  `tests/real_data/cif_api/manifest.json`. Full canonical-IR
  pins in `tests/real_data/expected/`; provenance, license, and
  the per-file notes in `tests/real_data/cif_api/SOURCE.md`. The
  seven files the parser rejects are `known_gap` pins; the gap
  notes live in the expected JSON files.

## Axis 1: space groups (230)

Invariant: for every space group number 1..230, the corpus holds a
file that (a) parses, (b) passes the validator, (c) carries an
IT-number tag equal to the group, and (d) carries a
Hermann-Mauguin name tag. The manifest records the COD entry, its
H-M symbol, its Hall symbol, and the candidate list used at fetch
time.

Fetch: `python3 tests/real_data/cod_sg/fetch.py`. It queries
`https://www.crystallography.net/cod/result?space_group_number=N&format=lst`,
downloads the first candidate at most 150 KB, and records JSON
metadata. Reruns resume from the manifest. See `tests/real_data/cod_sg/SOURCE.md`.

Why the light pin: a canonical-IR pin of 230 files would add about
2 MB of JSON and slow every run. The space-group axis protects
parseability and tag consistency, not value stability. If a value
regression inside these files matters, add the file to the
canonical corpus instead.

Observed tag drift: four files use the legacy `space_group_*`
spelling (`_space_group_IT_number`, `_space_group_name_H-M_alt`,
`_space_group_symop_*`) instead of the `symmetry_*` CIF core
spelling. The test accepts both.

## Axis 2: lexical and structural features

Invariant: each feature in the table of `tests/feature_coverage.rs`
has at least one corpus file as evidence. The guard prints the
evidence table. A corpus prune that removes the last evidence file
for a feature fails the build.

Features guarded: `?` unknown values, `.` inapplicable values,
`~` scripts, backslash letter escapes, indexed symmetry codes,
semicolon text fields, comment lines, hash inside quoted strings,
CRLF endings, non-ASCII UTF-8 content, multiple data blocks,
save frames, files of 100 KB or more.

## Axis 3: dictionary-item coverage

Invariant: the number of recorded dictionary items that occur in
the real-data corpora does not drop below the committed baseline
(`tests/dict_coverage_baseline.json`). Regenerate after corpus
changes with `cargo run --example dict_coverage_gen`. Raise the
baseline when coverage grows.

Current floor: 320 of 732 items (44%), over 247 files. The 436
distinct tags in use include tags outside the recorded inventory;
the test prints the list as a growth hint.

## Derived axis: crystal systems and Bravais lattices

The 230 space groups span all seven crystal systems and all
fourteen Bravais lattices by construction. Axis 1 therefore
covers the system and lattice axes. No separate test is needed.
The manifest records the H-M symbol per group for inspection.

## Deferred axes

- Stress and performance: add files of 1 MB or more (large
  reflection loops) and a parse-time budget. The 120 KB file
  covers the large end for now.
- Superspace and incommensurate entries: the API supports
  superspace group symbols; the 230-group axis is strictly
  three-dimensional. Add a small corpus of 4D/5D entries.
- Producer diversity: record the structure-refinement program in
  the manifest (`_computing_structure_refinement`) and guard the
  mix of SHELX, Jana, Olex2, and other producers.
- BOM handling: covered by the cif_api corpus (`bom.cif`,
  `bom_ver2.cif`), pinned by `real_data_verify`. A numbered
  fixture (`21_bom_utf8.cif`) would pin the BOM path in the
  ground-truth axis; the real-data pin covers the parse for now.
- Save-frame-heavy reports: the IUCr corpus here carries no save
  frames; only fixture 06 does. Fetch a COD entry whose report
  uses `save_` frames and add it to the canonical corpus.
