# Source of the cif_api corpus

The files in `tests/real_data/cif_api/` are the test-data CIF files
of the COMCIFS `cif_api` project, a C reference implementation of
the CIF 1.1 and CIF 2.0 formats. They are used here as regression
inputs for the parser (test axis: real-file pin).

- repo: `https://github.com/COMCIFS/cif_api`
- path: `test-data/` at commit `7882c1244bb4f69607561448ac82346f6637015f`
- fetched: 2026-10-13, with plain HTTP
  (`raw.githubusercontent.com`); blob SHAs verified against the
  GitHub contents API
- copyright: 2014, 2015 John C. Bollinger, per the upstream
  `test-data/README` notice
- license: GNU Lesser General Public License v3 or later, per the
  upstream `test-data/README` notice (the files are part of the
  CIF API distribution)
- credit: this corpus is the upstream project's test data; the
  author is credited in `AUTHORS` of the upstream repo

The expected JSON files in `tests/real_data/expected/` were
generated by the crate's own canonical encoder
(`cargo run --example gt_generate -- --real-data`). They pin the
parse output; they are a self-consistency pin, not an independent
ground truth.

## Not pulled

The upstream `test-data/` directory also holds `cif_core.dic` (a
DDL1 core dictionary, property of the IUCr) and `README` (the
license notice quoted above). Neither is a CIF file, so neither is
pulled here. The DDL1 dictionary is already sourced from the IUCr
archive in `tests/dict/` with its own provenance.

## Files

| file | dialect | what it pins |
|---|---|---|
| `10.cif` | 1.1 | translated end-of-line characters (VT `0x0B`, FF `0x0C`), semicolon text fields, a `1.25e+03` exponent form |
| `bom.cif` | 1.1 | a UTF-8 BOM as the whole file |
| `bom_ver2.cif` | 2.0 | a UTF-8 BOM before the `##CIF_2.0` magic |
| `cif11_unquoted.cif` | 1.1 | unquoted values with brackets, braces, and backslash escapes (the GitHub issue 22 cases) |
| `cif1_invalid.cif` | 1.1 | a value `['k']` that is invalid in CIF 1.1; accepted under the recorded 1.1 deviation (unquoted values may begin with `[`) |
| `cif1_quoting.cif` | 1.1 | single/double-quoted strings with embedded quotes |
| `comment_only.cif` | 1.1 | a file with no data block |
| `complex_data.cif` | 2.0 | a list of lists and a table of tables |
| `container_names.cif` | 2.0 | bracket/brace container names (`data_with[1]`, `save_with{2}`) |
| `empty.cif` | 1.1 | the zero-byte file |
| `list_data.cif` | 2.0 | lists: empty, `.`/`?` members, comments inside, quoted members |
| `nested.cif` | 2.0 | nested and sibling save frames |
| `simple_containers.cif` | 2.0 | multiple data blocks, save frames, name scoping |
| `simple_data.cif` | 2.0 | the value forms: `?`, `.`, unquoted, quoted, text field, `0.0625(2)`, quoted `?`/`.` |
| `simple_loops.cif` | 2.0 | loop rows of unequal length, a semicolon text value in a loop |
| `table_data.cif` | 2.0 | tables: empty, singleton, a comment after `{`, space keys |
| `text_fields.cif` | 2.0 | text fields: folding, lone-CR line terminators, `;;` empty text |
| `triple.cif` | 2.0 | triple-quoted single/double strings, multiline forms |
| `unicode.cif` | 2.0 | Unicode in comments, block/frame codes, item names, and values (U+2212, U+1063E, U+16A0, U+2820) |
| `ver1.cif` | 1.1 | the `##CIF_1.1` magic alone |
| `ver2.cif` | 2.0 | the `##CIF_2.0` magic alone (no trailing newline) |
