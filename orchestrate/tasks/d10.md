# Mission: D10 dictionary completeness research

## Context (you start from zero context)

The repo is `crystal-cif-io` v0.2.0, working branch `dev-0.2`.
The crate parses and writes CIF 1.1 and CIF 2.0. The `data_dict`
layer provides typed item enums per dictionary category
(`CifTerm`, `SingleValueTerm`, `LoopValueTerm`). It performs no
integrity check: a user can emit any subset of a category's items.
An incomplete cell (one length, no angles) writes without
complaint. The dictionary files are pinned in
`tests/dict/cif_core.dic` (DDL1, 734 items) and
`tests/dict/cif_core_shell.dic` (DDL2, the shell items). See
`tests/dict/SOURCE.md` for provenance.

The user decided D10 on 2026-10-13 (recorded in
`docs/roadmap-dict-items.md` sections 5 and 10): research the
mutual dependencies of the dictionary items, then add a
per-category builder layer built on the `bon` crate (3.x) for
compile-time required-field checking. This mission is the
research. The builder wave (D11) starts only after the user
reviews this document.

## Deliverables

1. `docs/dict-completeness.md` (new document), four parts:

   a. **Method.** The dictionaries are the source of truth.
      DDL1 items carry `loop_ _name` groups, `_type`,
      `_type_conditions`, `_enumeration_range`, and `_definition`
      text (the prose records dependencies: formulas, "must
      correspond to" rules). DDL2 items are save frames carrying
      `_type.source` (Measured, Derived, Assigned, Recorded,
      Related), `_method.expression` (the derivation formula),
      `_type.container`, `_type.dimension`, `_type.linked_item_id`,
      plus DDL1 `_list_link_child` and `_list_reference`.
      State which fields you read for each relation kind.

   b. **Relations.** Define the relation classes:
      Measured (the source-of-truth values), Derived (a formula in
      `_method.expression` or the DDL1 `_definition`), Assigned,
      Recorded (free-text notes), context (optional measurement
      items), linked (loop references between categories).

   c. **The `cell` category, the worked example.** A table of
      every cell item (core 22 plus the shell overlay, the `_su`
      items excluded): name, source class, range, container,
      expression present, notes. Then the definition modes: how
      many complete ways exist to define a cell and which items
      each way requires. For each mode state the derivable items
      and the cross-checks a builder can compute when two modes
      are present together. Then the cross-category edges.

   d. **The core structure categories.** The same analysis for
      `space_group`, `atom_site`, and `chemical_formula` (the
      minimal structure dataset): definition modes, required
      sets, derivable items, cross-checks, cross-category edges.

   e. **Builder input.** For each covered category: what a `bon`
      builder must require per mode, what consistency check to
      run when redundant modes are present, what cross-category
      links to validate. This section is the spec for the D11
      builder mission.

2. `codegen/extract_depends.py`: a python3 (stdlib only) script
   that reads the two pinned dictionaries and writes
   `codegen/depends.json`: per category, the item groups (from
   DDL1 `loop_ _name`), per item the source class, range,
   container, expression, and the cross-references pulled from
   the definition text. The committed JSON is generated by the
   script. Add a check that reruns the script and fails on diff.

3. `docs/roadmap-dict-items.md`: append a `D10a` row to the
   section 10 decision log: research complete, the categories
   covered, the open items that D11 must resolve.

## Prior findings (verify against the dictionaries, then extend)

Verified on 2026-10-13 against the pinned files:

- The core inventory records 22 `cell` items. The shell overlay
  adds 16: `metric_tensor`, `orthogonal_matrix`,
  `reciprocal_orthogonal_matrix`, `reciprocal_metric_tensor`,
  `vector_a/b/c`, `reciprocal_vector_a/b/c`, `atomic_mass`,
  `formula_units_z_prime`, `formula_units_z_prime_details`,
  `convert_uij_to_betaij`, `convert_uiso_to_uij`. Total 38,
  plus the four `cell_measurement_refln` loop items.
- The six direct parameters (`_cell_length_a/b/c`,
  `_cell_angle_alpha/beta/gamma`) are the source-of-truth
  values. The shell marks the rest `Derived`, `Assigned`, or
  `Recorded`, and carries the formulas:
  `volume = a*b*c*(1 - cos^2 a - cos^2 b - cos^2 c
  + 2 cos a cos b cos c)^0.5`; the reciprocal angles via the
  Buerger formula; `orthogonal_matrix` from the six parameters
  (Rollett axial assignment); `vector_a/b/c` from
  `orthogonal_matrix`; `reciprocal_vector_a = b ^ c / V`;
  `metric_tensor` from the vectors;
  `reciprocal_orthogonal_matrix = Inverse(Transpose(OM))`.
- Five equivalent complete ways to define a cell: the six direct
  parameters; the orthogonal matrix (3x3); the three vectors
  (3x3); the six reciprocal direct parameters; the metric tensor
  (symmetric 3x3, six independent entries). IUCr marks four of
  the five as derived from the direct six.
- Cross-category edges: `_cell_formula_units_z` from
  `chemical_formula` (structural, moiety, or sum);
  `_cell_formula_units_z_prime` = Z divided by the space group
  multiplicity; `_cell_measurement_wavelength` falls back to
  `diffrn_radiation_wavelength`; the `refln_index_h/k/l` values
  must correspond to the cell; `atom_site_fract_*` coordinates
  are defined against the cell.
