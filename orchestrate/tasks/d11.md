# Mission: D11 builder wave 1 (the `bon` builders)

## Context (you start from zero context)

The repo is `crystal-cif-io` v0.2.0. The provisioned worktree is on
branch `dict-items/d11`, based on `dev-0.2` after the D10a merge.
The crate parses and writes CIF 1.1 and CIF 2.0. The `data_dict`
layer types items per category (`CifTerm`, `SingleValueTerm`,
`LoopValueTerm`). It performs no integrity check: any subset of a
category's items writes without complaint.

The D10a research (merged) provides two inputs:

- `docs/dict-completeness.md` section 5: the builder input spec
  (roles per category: `required`, `optional`, `derived`, `su`,
  `loop`, `enum`, plus the "Builder shape" subsection).
- `codegen/depends.json`: the machine-readable item map (94
  categories, 1185 items). Read the category you are building.

Decision D11 (roadmap, 2026-10-13) adds a per-category builder
layer on the `bon` crate. The builders enforce the needed fields
at compile time.

## The user's decisions (2026-10-13, binding)

1. Equivalent minimum entry sets own their own individual
   builders. The crate adapts to different habits.
2. `cell`: two builders. One needs `a b c alpha beta gamma`.
   The other needs the three lattice vectors.
3. `space_group`: one builder, three entry points (`IT_number`,
   `name_Hall`, `name_H-M`). Resolution through the
   `crystallographic-group` crate. The computed items are outputs,
   not inputs.
4. `formula_units_Z`: not manual input. A structure-level
   computation derives `Z` from the `atom_site` loop, the
   chemical formula, and the `space_group` multiplicity. A
   supplied `Z` is cross-checked.
5. Code style: no comments where the code states the intent.

## New dependencies

- `bon` 3.x (3.10 on crates.io): the builder macro. A missing
  needed field fails the build at the `build()` call.
- `crystallographic-group` 0.4 (published, the user's crate):
  `SpaceGroupTable::all()` with `number_by_hm` and `number_by_hall`;
  `SpaceGroup::try_from_str` (Hall notation); `number()`,
  `hm_symbol()`, `crystal_system()`, `general_positions()`;
  `GeneralPositions::core_position_set()` (the Seitz matrices),
  `derive_full_sets()`, `formulas()`.

## Deliverables (a new `src/builder` module, re-exported at the
crate root)

The builders materialize `DataItems` through the existing
`data_dict` traits. Do not rewrite the dictionary layer.

1. `cell`: two builders per section 5.
   - `CellBuilder`: the direct six needed (`Numeric` x3,
     `CellAngle` x3). The optional fields of the section 5 table.
     Derived values (`volume`, the reciprocal items,
     `orthogonal_matrix`, `metric_tensor`) compute at build. A
     supplied derived value cross-checks within tolerance. A
     mismatch rejects with a `Result`, never a panic.
   - `CellVectorsBuilder`: the three vectors needed.
2. `space_group`: `SpaceGroupBuilder` with `from_it_number`,
   `from_hall`, `from_h_m`. Resolution through
   `crystallographic-group`. The computed items emit
   (`crystal_system`, `Bravais_type`, `centring_type`,
   `multiplicity`). A supplied value cross-checks.
3. The `space_group_symop` loop builder: `operation_xyz` needed
   per row. The row ordinal is `id`. `R`, `RT`, `T`,
   `Seitz_matrix` derive from the Seitz lists of the resolved
   group. The row text cross-checks against the lists.
4. The `atom_site` row builder: `label` plus `type_symbol`
   needed. One coordinate mode per row (fractional or Cartesian,
   an exclusive enum field). The displacement-type enum is
   needed (the aniso or iso choice per `adp_type`; the aniso
   `U`/`B` payloads ride on the aniso arm). The `_su` twins are
   optional.
5. `chemical_formula`: `structural` needed. The other spellings
   optional. `weight` is a helper function that takes the
   density argument. It is not a builder field.
6. The structure-level `Z` helper: computes `Z` from the
   `atom_site` rows, the formula, and the multiplicity. A
   cross-check helper takes a supplied `Z` and a tolerance.
