## Scope (roadmap section 13.2 to 13.4)

1. Dialect detection. The magic code `##CIF_2.0` as the first
   characters of the file, after any byte order mark, enables the
   2.0 value rules. Anything else stays 1.1. In the 1.1 dialect
   the magic code remains an inert comment line. The parser holds
   a dialect flag.
2. A `Value::List(Vec<Value>)` variant. Nested lists are legal.
   Export `List` (or the variant) from the crate root next to
   Numeric.
3. The 2.0 unquoted-value restriction. `[`, `]`, `{`, or `}`
   inside an unquoted value is a parse error in the 2.0 dialect.
   In the 1.1 dialect they stay plain characters, as today. The
   value rule becomes `list | <current choice>`, where `list`
   parses only in the 2.0 dialect.
4. A `Matrix` constructor from list values, on the existing Matrix
   type from T0 (src/grammar/matrix.rs, section 12.2). It takes a
   List of Numeric values, rejects non-numeric elements and ragged
   shapes, and checks the dictionary shape when given one.
5. Canonical JSON. The value kinds gain one:
   `{ "kind": "list", "values": [ ... ] }` with nested value
   objects. New fixtures carry `schema_version: 2`. Existing
   fixtures keep version 1. The groundtruth harness
   (tests/ground_truth.rs and examples/gt_generate.rs) accepts
   both versions.

## Out of scope (roadmap section 13.3)

No table values, no triple-quoted strings, no other 2.0 syntax.
