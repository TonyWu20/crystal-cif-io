## The user's decisions (binding, from wave 1)

- D12a: the category struct lives in `data_dict/core_cif/
  <cat>/<cat>.rs`. The entry files keep the per-entry value
  types.
- D12b: every struct field is `Option<T>`. Reads are tolerant.
  `validate` reports named required items. These 16 categories
  carry no required-set spec. `validate` gains no new checks
  for them.
- D12d: a value class mismatch on a typed item is a
  `CifError::ValueClass` in the `from_block` error list.
  Unknown tags land in `extra`.
- D12e: save frames land in `extra`, order kept.
- The newtype convention: a closed-set item types to an enum.
  A ranged item keeps `Option<Numeric>` unless an existing entry
  newtype exists (reuse it). A plain item keeps the shared value
  type.

## The work, in order

1. For each of the 16 categories:
   - a struct in `<cat>/<cat>.rs`: public `Option<T>` fields,
     Default, one field per registry item.
   - loop categories: the row struct. `CoreCif` holds
     `Vec<Row>`. Mixed categories: the single struct and the
     row struct.
   - closed-set items: a new enum in an entry file of the
     category (the `adp_type.rs` pattern). The code set copies
     the `closed_values` of `depends.json`. Register the module
     in the category `mod.rs`.
   - ranged items: `Option<Numeric>`. Reuse an existing entry
     newtype when one exists.
   - plain items: `Option<CharString>`.
   - register the struct module in the category `mod.rs`.
2. Extend `CoreCif` in `crystal_cif_io/src/core_cif.rs`:
   - one field per category. `Vec` for the loop-row categories.
   - `from_block`: call the category `from_members`. Keep the
     residue.
   - `to_block`: emit the wave 2 field blocks after the wave 1
     blocks, then `extra`. Mark the new lines with
     `// T5 wave:` so the parallel wave merges stay clean.
   - `validate`: no new checks (binding decision above).
   - the crate root re-exports: add the new category structs to
     the `pub use` block in `src/lib.rs`.
3. `CHANGELOG.md`: an Unreleased entry names the 16 categories
   and the tier.
4. Tests, `crystal_cif_io/tests/typed_round_trip_w5.rs`:
   - a round-trip test over a ground-truth corpus file that
     carries the tier items:
     `crystal_cif_fmt/tests/real_data/` (the `iucr`, `cod`, and
     `real_data` corpora) or
     `crystal_cif_fmt/tests/fixtures/`. Pick two or three files
     with the tier tags. Read, rewrite, re-read. The typed
     fields and `extra` are stable.
   - a residue test: a foreign tag and a save frame of the tier
     land in `extra`, order kept.
   - a closed-set spot check: one enum of the wave parses its
     dictionary codes and rejects an outside code.
5. Run `cargo test` in the worktree. Both crates green.
